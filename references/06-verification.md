# 06 · 验证层（三重验证 + 保真度评分卡）

正流对所有模式强制共用一套验证标准，确保蒸馏出的 Skill"可信、可测、可维护"。

## 一、三重验证（Triple Verification）—— 观点/知识单元能不能收录

任一被提炼的单元（心智模型 / 原则 / 框架 / 能力卡）必须过三关：

1. **跨域出现（Cross-domain）**：在 2+ 个独立来源/领域里都出现过，不是随口一说或孤例。
2. **预测力（Predictive power）**：能推断该对象面对**新问题**时的立场，而非只解释已知行为。
3. **排他性（Non-obviousness）**：不是"所有聪明人都会这么想"的常识——有该对象的独特印记。

> 三关全过才收录；任一不过则降级为"参考/未决候选"，保留可审计，不进主结构。

## 二、质量验证（Quality Gate）—— Skill 能不能交付

- **已知问题测试**：拿 3 个该对象公开回答过的问题测试，**方向一致**才通过。
- **未知问题测试**：拿 1 个该对象**没讨论过**的问题测试，Skill 应表现**适度不确定**，
  而非斩钉截铁（防止过度自信的幻觉）。
- **诱饵/混淆测试**（仓颉式）：设计诱导性问题与跨 Skill 混淆测试，失败则回炉重建。

## 三、保真度评分卡（Fidelity Scorecard）—— 5 维盲测

独立双 Agent 盲测，5 个维度各打分，综合 ≥85 分为 A 级：

| 维度 | 考察点 |
| --- | --- |
| 立场一致性 | 面对同类问题立场是否稳定不漂移 |
| 风格辨识度 | 能否被辨识出"就是那个人/那本书的味道" |
| 边缘诚实度 | 在边界/未知问题上是否诚实而非臆断 |
| 来源透明度 | 每个结论是否可追溯出处 |
| 结构完整度 | 是否满足对应模式的必备结构 |

> 一个不告诉你"局限在哪"的 Skill，不值得信任。诚实边界是必填项，不是装饰。

## 四、结构自检（脚本化）

`scripts/verify.py` 可对任意蒸馏产物做结构巡检：

- 是否有 `SKILL.md` 且含 `name` + `description` frontmatter；
- 人物类是否含 Persona 六槽位（硬规则/身份/表达/决策/人际/纠正）或等效五层；
- 内容类是否含 R/I/A1/A2/E/B 能力卡与 Known limitations；
- 是否含"诚实边界 / 已知局限"段落。

不达标则阻断交付并提示缺失项。
